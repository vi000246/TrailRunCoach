## 2. 設計

### 2.1 目錄結構

```
backend/i18n/
  __init__.py        # _()、N_()、current_locale()、use_locale()
  fmt.py             # 數字、日期、星期、時長、距離（server 端）
  locales/en.json    # 後端：{ "中文 msgid": "English" | {"one": …, "other": …} }
  locales/en.meta.json  # { msgid: {"draft": true, "src": "engine/status.py:313"} }
  glossary.json      # 術語表（§5），測試會讀
backend/static/i18n/
  i18n.js            # t()、fmt.*、語言切換；在 shell.js 之前同步載入
  zh-TW/{shell,common,overview,schedule,racepower,plan,viewer,…}.json
  en/{同上}.json
views/i18n/en.json   # { "training": { "<chart id>": {title, description, series: {…}} } }
```

`zh-TW` 後端不需要目錄檔（msgid 就是原文）。`ja` 等之後只要加檔案。

### 2.2 前端：語意 key ＋ server 端注入

- 頁面現在是 `FileResponse(STATIC / "x.html")`。改成共用的 `render_page("x", locale)`：
  1. `<html lang>` 換成目前語系；
  2. 把 `data-i18n="ns.key"`（文字）與 `data-i18n-attr="title:ns.key;placeholder:…"`（屬性）的元素在 server 端直接換成譯文（每個語系渲染一次、以檔案 mtime 快取）——**沒有先閃中文再換英文**；
  3. 內嵌 `<script>window.__I18N__ = {locale, catalog}</script>`（只放這頁用到的 namespace＋`common`＋`shell`），JS 樣板字串用 `t("overview.ramp.good", {ramp})`。
- `t()` 的佔位符語法和後端一致：`{name}`、`{n, plural}` 用 `{"one","other"}` 物件。
- 純靜態文字以外，**JS 裡的 225 句與 HTML `<script>` 裡的字串**全部改 `t()`；這是工作量的大宗。
- shell.js 的 `PAGES`（name / short / purpose）改成 key；導覽列右側加「中文 / EN」切換（寫 cookie `lang`，一年，`SameSite=Lax`，然後重新載入）。

### 2.3 後端：`_()` ＋ 請求語系

- 中介層從請求決定語系（§2.7），放進 `contextvars.ContextVar("locale")`。和 `auth-and-demo.plan.md` §2 的 tenant context **放在同一個 middleware**。背景執行緒（`warm_up`、自動同步、每日備份）用 `use_locale(帳號設定 or 預設)`。
- 寫法：
  ```python
  verdict = _("每週 +{ramp:.1f}，可長期維持的增幅（1–3；菁英 3–5）", ramp=ramp)
  TYPE_LABEL = {"road": N_("路跑"), "trail": N_("越野"), "baiyue": N_("百岳")}   # 用時才 _(TYPE_LABEL[k])
  ```
  `_()` 用 `str.format`，所以 `:.1f` 這類格式在兩種語言都保留。f-string 轉 `_()` 用 codemod（抽出 `{expr:spec}` → 具名參數），簡單的可自動，巢狀運算式人工。
- 出處引文（`SRC_TP_TSB` 這類）也是 msgid；人名、書名、論文年份照原樣。
- 引擎回傳結構不變（仍是 `verdict / why / action` 文字），**但凡前端或後端拿文字做判斷的欄位，同時加代碼欄位**：`mode: "run"|"walk"`、`pack_src_kind: "default"|…`、`status_code: "productive"|…`、`protocol` 不再由 title 推。11 處前端比對＋已知的後端比對（`protocol_of(title)`）先改成看代碼。
- 快取：含文字的快取 key 加 `current_locale()`；不含文字的（FIT dataset、數值）不動。

### 2.4 存進 DB 的產生文字

- 自動產生的課表（`plan_auto`、模板、間歇庫）存 `gen_key` / `variant_key` ＋參數；讀出時若 `source` 是自動產生且使用者沒改過，就依目前語系重新產生 `title / target / detail`。
- 使用者改過的文字是使用者內容，不翻。既有的中文資料列保持原樣（沒有 key 的就當使用者內容）。
- COROS 推送的課表名稱／步驟說明用**帳號設定的語系**（手錶上存著，不跟著請求變）。

### 2.5 API 錯誤

- 新增 `UserError(msgid, code=None, **params)`；全域 handler 回 `{"detail": {"code": "PUSH_PAST_WEEK", "message": <翻好的文字>, "params": {…}}}`，HTTP 狀態不變。
- 40 個帶中文的 `HTTPException` 與 31 個會被 `str(e)` 傳出去的 `ValueError` 改成 `UserError`。英文的開發者訊息（`"scope must be one of …"`）保持英文、不進目錄。
- 前端統一 `apiError(res)`：有 `message` 就顯示，舊格式字串照舊顯示。

### 2.6 views JSON

1. 每個 dashboard 和 chart 加 `id`（slug，例如 `pmc-all`、`weekly-volume`）；`wko5_fixes.json` 的對應改用 id（保留中文名稱當註解）。這一步不改任何顯示，可以先單獨合併。
2. sidecar `views/i18n/en.json`：`{view: {dashboards: {id: name}, charts: {id: {title, description, y_axis: {…}, series: {"CTL 體能": "CTL Fitness", …}, power_note}}}}`。series 用原中文名當 key（同一張圖內不重複）。
3. `api/wko5views.py` 在套完 fixes **之後**、回應之前套翻譯；快取 key 加語系。缺的欄位退回原文。

### 2.7 語言偵測與記憶

順序：`?lang=xx`（同時寫 cookie）→ cookie `lang` →（第二階段登入後）帳號設定 → `Accept-Language`（依 q 值，取第一個支援的）→ 實例預設 `TRC_DEFAULT_LOCALE`（自架預設 `zh-TW`；示範實例設 `en`，但 `Accept-Language` 是 zh 的訪客仍拿到 zh-TW）。

對應：`zh`、`zh-TW`、`zh-Hant*`、`zh-HK`、`zh-MO` → `zh-TW`；`zh-CN`、`zh-Hans*` → 暫時 `zh-TW`（之後可以加 OpenCC 轉的 `zh-CN`）；`en*` → `en`；其他 → 實例預設。

回應加 `Content-Language` 與 `Vary: Cookie, Accept-Language`（反向代理才不會快取錯語言）。

### 2.8 退回規則

`en-GB` → `en` → `zh-TW`（原文）。前端 key 在 `en` 缺就用 `zh-TW` 的值；後端 msgid 缺就回 msgid 本身。開發模式 `?i18n_debug=1`：缺的字串用 `⟦…⟧` 包起來，方便在畫面上找；正式環境只記數量（每個 msgid 記一次 log）。

### 2.9 數字、日期、單位

- 前端 `fmt.num(x, d)`、`fmt.pct`、`fmt.date(d, "md" | "mdw" | "ymd")`、`fmt.weekday(d, "short")`、`fmt.dur(s, "hm" | "hms")`、`fmt.pace(s_per_km)`、`fmt.dist(km)`、`fmt.elev(m)`，底層 `Intl.NumberFormat / DateTimeFormat(locale)`。
- 後端 `fmt.py` 同一套函式名；兩個語系先手寫，超過兩個語系再考慮引入 Babel。
- 目前的寫法對照：`10/2（週四）` → en `Thu 10/2`；`3 小時 20 分` → `3h 20m`；`週{wd}` 9 份全換 `fmt.weekday`；ECharts calendar 的 `nameMap` 依語系。
- **單位維持公制**（km、m、kg、°C、min/km）。所有距離／爬升／體重顯示都走 `fmt.dist / fmt.elev`，之後 km/mi、m/ft 只要改那裡＋加一個「單位」偏好（不綁語系，美國人用中文也可能要 mi）。輸入欄位（體重、背負、距離）同理。

## 3. 工具

### 3.1 `backend/scripts/i18n_extract.py`

- Python：用 `ast` 找 `_()` / `N_()` 的第一個參數 → 更新 `en.json`（新 msgid 值為 `null`）、`en.meta.json`（`src` 位置）；**另外列出還沒包起來的中文字串**（字面＋f-string，排除 docstring / 註解）。
- HTML / JS：列出不在 `data-i18n`、`t()` 裡的中文文字節點、屬性、字串字面。
- 檢查 zh 與 en 的佔位符集合一致、en 裡沒有中文（術語表允許的除外，例如「百岳」的括號原文）。
- 列出孤兒：en 有、程式碼已經沒有的 msgid（中文原文改過就會出現），用相似度提示「可能是改名」。
- 允許清單 `backend/i18n/allow_cjk.txt`：故意保留的中文（比對使用者活動名稱的 regex，如 activity_tags 的「賽／馬拉松」，共約 21 行；`backend/data/baiyue.json` 山名；AI prompt 裡的中文知識）。
- 輸出 `i18n_report.json`（每檔：已包、未包、缺 en、draft 數），單一行程跑完（遵守不平行灌行程的規則）。

### 3.2 `backend/tests/test_i18n_coverage.py`

1. **棘輪**：`backend/i18n/baseline.json` 記每個檔案「未包的中文字串數」，只能變少；新增一個沒包的中文 UI 字串 → 失敗。
2. **已完成的 namespace / 模組**（清單在 baseline 裡，隨 phase 增加）：每個 key / msgid 都要有非 `null` 的 en。
3. 佔位符一致、en 無中文、術語一致（glossary 的中文詞出現在 msgid 時，en 必須用指定譯名）。
4. views：每個 chart 有 id、sidecar 沒有指向不存在的 id。
5. 一個 en 渲染的煙霧測試：用合成資料（不碰 `~/WKO5`、`~/.wko5coach`）呼叫總覽 API，斷言回應裡沒有中文。

## 4. 翻譯流程

1. 開發者照常寫中文 → 跑 `i18n_extract.py` → 新字串出現在 `en.json` 為 `null`。
2. 機器初稿：Claude 一次吃一個 namespace，提供術語表、msgid 的 `src` 程式位置與前後文、這頁在做什麼；產出寫進 en 並標 `draft: true`。
3. 擁有者在示範實例切到 EN 審頁面（`?i18n_debug=1` 會把 draft 也標出來）；審過的去掉 `draft`。
4. phase 驗收：該 phase 的 namespace 缺 0、draft 0。
5. 風格：英文句子短、用祈使句（action 欄位）、跑者通用講法；不翻人名、書名、出處；數字和單位之間空格（`42 km`）。

## 7. 和其他工作的關係

- **`推估 → 推估` 改名先做**：msgid 是中文原文，改名會讓所有含「推估」的 msgid 變孤兒；先改名再抽字串，翻譯只要做一次。
- **`generalize-athlete.plan.md`**：B2「Stryd 文字跟著功率來源」、B3「AMS 文字」、B8「D\* 改名與註解」都在改中文句子，要在對應頁的 phase 之前落地；B3 的 `athlete.region` / `timezone` 和本計畫的語系**分開**（台灣人可能用英文、外國人可能用中文），但示範實例可以用 region 給單位預設。
- **`auth-and-demo.plan.md`**：語系和 tenant 共用同一個請求 context middleware；示範的沙盒 cookie 與 `lang` cookie 並存；示範實例的 `TRC_DEFAULT_LOCALE=en`。第二階段登入後語系存在帳號設定。
- **測試**：預設語系 `zh-TW`，88 個有中文斷言的測試不動；新測試遵守「不依賴 WKO5 資料夾」。
- 不碰 port 8000 的正在執行實例與 `~/.wko5coach`；所有驗證用合成資料。

## 8. 擁有者決定（2026-10-02）

1. TSB／Form 區間英文名**照 TrainingPeaks 原名**：High Risk／Optimal／Grey Zone／Fresh／Transition（§0、§5、`glossary.json`）。
2. 不支援的語言**一律 `en`**（`request_context.from_accept_language`、`?lang=xx`）；沒有任何語言偏好時才用實例預設。
3. 「百岳」**每頁第一次寫全稱**：中文「百岳（Taiwan's 100 Peaks）」、英文 "Taiwan's 100 Peaks (Baiyue)"。
4. 自動產生的課表文字**跟著語言切換**：讀出時依語系產生、不存句子（§2.4）；句子多，放 P3 做。

## 9. P0 實作紀錄（`feat/i18n-p0`）

- `backend/i18n/__init__.py`：`_()`／`N_()`／`use_locale()`／`UserError`；`locales/en.json`＋`en.meta.json`（目前只有 `api/backup.py` 兩個示範 msgid）。`fmt.py`：weekday／date／num／pct／dur／pace／dist／elev。
- `backend/request_context.py`：純 ASGI middleware（tenant 之後也放這裡），順序 `?lang=`（寫 cookie）＞ cookie ＞ `ACCOUNT_LOCALE` hook（目前回 None）＞ `Accept-Language` ＞ `TRC_DEFAULT_LOCALE`；回 `Content-Language`、`Vary: Cookie, Accept-Language`。新開的 thread 從 zh-TW 開始，要別的語系用 `use_locale()`。
- `backend/i18n/pages.py` `render_page()`：所有頁面路由（含 `/api/v1/static/<name>.html`，例如 compare.html）都走它；`<html lang>`、`data-i18n`／`data-i18n-attr` server 端替換（`<script>` 內不動）、內嵌 `window.__I18N__` 並最先載入 `static/i18n/i18n.js`（`t()`、`I18N.fmt.*`、`I18N.setLocale()`）。
- shell：導覽文字改讀 `static/i18n/{zh-TW,en}/shell.json`（en 已翻、baseline `complete: ["shell"]`），右側「EN／中文」切換鈕寫 cookie `lang`（一年、`SameSite=Lax`）後重新載入。
- 星期：overview／schedule ×2／wko5_viewer 的陣列換成 `I18N.fmt.weekdays()`；engine 的 `adapt.wd`、`b2b.wd`、`suggestions._md` 換成 `fmt`。`overview.WEEKDAYS`（當資料值用、`projection` 拿來 `.index()`）與 `plan_prefs.WD_ZH`（嵌在句子裡）不是機械替換，留給 P1／P3。
- views：三個 view 的 dashboard／chart 都有手寫 slug `id`；`parse_view` 保留 id、缺的用標題產生（`viewids.py`）；WKO5 `.wko5chart` 讀進來也補 id，`wko5_fixes.json` 改用 `chart_id`／`dashboard_id` 對應（中文名稱保留當提示）。sidecar `views/i18n/en.json` 是全部 id 的空殼；`viewi18n.translate_views` 在 fixes 之後套（目前全是 null，不改任何顯示）。render cache key 在非 zh-TW 時加語系。
- 工具：`backend/scripts/i18n_extract.py`（`--write`／`--report`／`--update-baseline`／`--check`）；`backend/tests/test_i18n_coverage.py` 棘輪目前 **report-only**（baseline `enforce: false`，超過只發 warning），P1 起各 phase 翻完再改 `enforce: true`。基準：7,023 個未包的中文字串、129 個檔案。
