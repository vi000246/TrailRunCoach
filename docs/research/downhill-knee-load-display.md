# 下坡的膝蓋負荷怎麼顯示：不要丟掉低步頻的步、下坡負荷圖加步頻（SP-196 後續）

> 設計日期：2026-10-06。只寫設計，沒有改程式。基準 commit `47c5a6e`。
> 起因：使用者指出，「跑姿與膝蓋負荷」卡把步頻低於 130 spm 的步都丟掉，但越野跑的下坡步頻常常到不了 130，而下坡正是最容易受傷的地方。使用者也要求「每週下坡衝擊負荷」圖加上步頻，並決定登山杖比較圖放在分析頁的「能力」分頁。
> 相關文件：`trekking-poles.md` §5.1、`downhill-recovery.md`（下坡損傷）、`baiyue-technical-terrain.md` §1（下山跌倒）。
> 標記：**已驗證**／**推估**，同其他研究文件。

## 摘要

1. **問題確定存在。** 卡片用的步段遮罩是「在移動、而且步頻 ≥ 130 spm」（`backend/engine/workout_review.py:1208–1232`，`_run_work`）。這個遮罩是為了「跑姿隨疲勞的變化」設計的，用在膝蓋負荷上，會把小碎步下坡、走下坡、技術下坡全部丟掉。
2. **建議：膝蓋負荷改用「所有移動中的步」，步頻從篩選條件改成顯示的指標。** 「跑姿飄移」（`form_drift`）維持 130 的規則，因為它問的是跑步姿勢，不是負荷。
3. **下坡負荷圖**是分析頁 →「訓練量」分頁的「每週下坡衝擊負荷（參考・自訂指標）」（`views/training.json`，id `weekly-downhill-load`）。它只在「設定 → 主要訓練項目 = 越野」時出現（`backend/static/wko5_viewer.html:576–580`），所以主要訓練項目是路跑時看不到。建議加一條右軸折線：陡下坡（< −8 %）的平均步頻，越野跑、登山各一條。
4. **登山杖比較圖**放在分析頁 →「能力」分頁，排在「下坡腳程（每小時下降）」旁邊（使用者決定）。

## 1. 現況

### 1.1 「跑姿與膝蓋負荷」卡

- 位置：活動頁（單次活動），`backend/static/wko5_viewer.html:3754` 起；後端 `workout_review.py:1253–1310`（`form_bins`）、`:3531–3645`（`form_profile`）。
- 指標：ILR、LSS（Stryd 才有）、衝擊 G、每公里衝擊量（推估）、kleg、觸地時間、步頻、垂直振幅（`workout_review.py:1235`）。
- 兩種看法：依坡度箱（陡下坡排最前面），或依「做功的每 10 %」看後段變化；都和「平常」（過去活動同一格的中間 50 %）比。
- 步段：`form_bins` 用 `_run_work` 的遮罩，「Running = moving and, with a cadence channel, ≥ 130 spm」（`workout_review.py:1214–1215`）。所以**低於 130 spm 的步不進任何一格，也不進「平常」**。
- 判讀提示：衝擊高於平常、步頻低於平常時，提示加快步頻（Heiderscheit 2011，`workout_review.py:3540–3552`）。

### 1.2 每週下坡衝擊負荷

- 位置：分析頁（趨勢）→「訓練量」分頁，第 4 張（`views/training.json` dashboards[1].charts[3]）。
- 內容：每週堆疊長條（路跑、越野跑、登山健行），單位「等效 km」：只算陡於 −3 % 的路段，坡越陡、速度越快權重越高（Gottschall & Kram 2005、Keller 1996，自訂組合，`backend/engine/algorithms/chart_metrics.py:155–178`）。
- **不用步頻**：公式只有坡度和速度。
- 只在主要訓練項目 = 越野時顯示（`"sports": ["trail"]`）。總覽的「下坡負荷」狀態卡（`backend/engine/status.py:760–788`）用的是同一個公式。

### 1.3 能力分頁

- 分析頁 →「能力」（`views/training.json` dashboards[3]）已經有：上坡腳程、穩定爬坡 VAM:HR、**下坡腳程（每小時下降）**、爬升密度等，越野相關的都標 `"sports": ["trail"]`。

## 2. 為什麼不能丟掉低步頻的下坡

| 依據 | 內容 | 等級 |
|---|---|---|
| 使用者的觀察 | 越野跑的下坡步頻常常到不了 130 spm | 使用者資料（這次沒有讀） |
| Faulhaber 2017（`baiyue-technical-terrain.md` §1） | 跌倒受傷的健行者 75.3 % 在下山時跌 | 已驗證 |
| Bontemps 2020 等（`downhill-recovery.md` §1–§2） | 肌肉損傷主要來自下坡；越陡、越快、越久損傷越大 | 已驗證 |
| Van Hooren 2024（`downhill-recovery.md` [D21]） | 下坡增加髕股關節的負荷；**步頻增加，所有組織的累積負荷都下降** | 已驗證（摘要） |
| Schwameder 1999（`trekking-poles.md` [T5]） | 下坡**走路**的膝關節受力也很大，用杖可少 12–25 % | 已驗證（摘要） |

所以：

- 低步頻的下坡**不是**「沒在跑所以不重要」，常常正是負荷最集中的地方（推估）。
- 步頻本身就是降低膝蓋負荷的手段 [D21]，應該**看得到**，而不是被拿來篩掉資料。
- 「130 spm 以下就是走路」在下坡不成立；在陡下坡，步頻低可能只是小心、技術路段或步幅受限（推估，依使用者觀察）。

## 3. 設計：膝蓋負荷卡

### 3.1 步段：所有移動中的步

- 卡片改用「在移動」的遮罩（`moving_mask`，和 `_run_work` 第一步相同），**不再用步頻篩**。
- `form_drift`（跑姿飄移）和它的判讀維持 130 spm，因為它比的是跑步姿勢隨疲勞的變化，混進走路會失真。
- 兩者分開後，`form_bins` 不再共用 `_run_work` 的遮罩；做功的十等分照舊用全部移動中的步算（有功率用功率，沒有用時間）。

### 3.2 步頻改成顯示，不當篩選

- 每個坡度箱多一欄「步頻 < 130 的比例」，讓人看得出這一格多少是小碎步或走路。
- 下坡箱的步頻照舊和「平常」比，現有的提示（衝擊高、步頻低 → 縮步、加快步頻）**也適用在下坡**，文字改成「下坡縮小步幅、加快步頻可以減少膝蓋負擔」（Van Hooren 2024 [D21]、Heiderscheit 2011）。
- 上坡（≥ 15 %）步頻低多半就是走路，提示不適用，不顯示。

### 3.3 「平常」要同類比同類

- 「平常」改用同樣的遮罩重算，否則新的一次（含低步頻）會和舊的平常（不含）比，系統性偏高或偏低。
- 越野跑和登山健行分開算平常（登山常常背包、用杖、坡更陡）。活動類別用 `activity_tags` 的 activity_type。
- 有標「有杖／沒杖」的（`trekking-poles.md` §5 #1），之後可以再分；第一版不分。

### 3.4 裝置在低步頻時可能沒有衝擊值

- Stryd 的 ILR、LSS 和手錶的衝擊 G，**走路或很慢時有沒有輸出，這次無法確認**（沒有讀資料）。
- 設計：某一格沒有衝擊值時顯示「–」，註明「這段沒有衝擊資料（慢速或走路時裝置可能不輸出）」；步頻、觸地時間、每公里步數照常顯示。
- 每公里衝擊量（G × 每公里步數）在慢速時會變大，這是真的（每公里踩更多步），不是錯誤；說明文字要寫清楚。

### 3.5 快取

- 活動的檢視結果有版本號（`workout_review.py:79` 一帶的 v13 說明）。改遮罩要升版本，讓舊活動重算，否則平常會新舊混在一起。

## 4. 設計：每週下坡衝擊負荷加步頻

- 加一條**右軸折線**「陡下坡步頻（spm）」：每週在坡度 < −8 %、移動中的時間加權平均步頻，越野跑、登山健行各一條，顏色跟長條一致、用虛線。
  - 用 −8 % 不用 −3 %：緩下坡的步頻接近平路，會把差異稀釋；−8 % 是回測的坡度分界（`backtest.py:105`）。
  - 下坡時間太少的週（例如 < 10 分鐘）不畫點，避免一兩分鐘的雜訊（比照「下坡腳程」的 10 分鐘門檻）。
- **衝擊公式不改。** 步頻怎麼加權進負荷沒有驗證過的係數；先並排顯示，讓人看得到「量變多時步頻有沒有跟著掉」。
- 說明文字加一句：「步頻越高、步幅越小，膝蓋負擔越小（Van Hooren 2024）；下坡量增加時步頻掉下來，要多注意。」
- 實作注意：
  - 步頻通道的單位要確認（後端用 strides/min，130 spm = 65，`workout_review.py:1208`）；圖上統一顯示 spm。
  - 如果圖表運算式不能做「每週兩個總和相除」的加權平均，就改由後端算每週序列。
- 可見度：目前只在主要訓練項目 = 越野時出現。要不要在路跑模式下、近 12 週有越野或登山下坡時也顯示，留給使用者決定（§6）。

## 5. 設計：登山杖比較圖（放在能力分頁）

- 位置：分析頁 →「能力」，排在「下坡腳程（每小時下降）」後面，`"sports": ["trail"]`（使用者決定）。
- 內容（沿用 `trekking-poles.md` §5.1）：依坡度箱（≤ −15、−15～−8、−8～−3 %，以及 ≥ 15 % 的陡上坡），有杖、沒杖各一個點：
  - 下坡：垂直速度（m/h）、步頻、衝擊（有的話）；
  - 陡上坡：同心率的 VAM。
  - 每個點標樣本數，n < 3 不畫。
- 步段用 §3.1 的「所有移動中的步」，否則用杖的走路時間會被丟掉。
- 只給常用杖的人：近 365 天標「有杖」≥ 5 次、「沒杖」≥ 5 次。現在的圖表清單只能依「主要訓練項目」和「使用功率」過濾（`wko5_viewer.html:576–580`），要多一種條件（例如圖表設定 `"needs": "poles"`，由後端回傳是否達標）。
- 圖上註明：有杖的日子常常也是背包較重、坡較陡、走得較久的日子，差異不一定是杖造成的。

## 7. 需要使用者決定的事

1. **下坡負荷圖要不要在路跑模式也顯示？** 現在主要訓練項目是路跑就看不到。我建議：近 12 週有越野或登山下坡時就顯示。
2. **步頻折線用 −8 % 還是 −3 % 的下坡？** 我建議 −8 %（理由見 §4）。
3. **#1 會讓每一次活動的「平常」重算，舊的比較結果會變。** 我建議接受。

### 已決定（2026-10-06，使用者）

1. **下坡負荷圖的顯示規則不改**，維持「主要訓練項目 = 越野才顯示」。使用者看不到這張圖，是因為最近越野跑得少，自動判斷成路跑；程式沒有壞。
2. **主要訓練項目的自動判斷加一條：A 賽或 B 賽只要有越野賽或百岳，就判成越野。** 見下面 #5。

| # | 標題 | 優先度 | 驗收條件草案 |
|---|---|---|---|
| 5 | 主要訓練項目自動判斷：A 或 B 賽有越野／百岳就算越野 | P2 | ① `primary_sport.suggest` 的順序改成：(a) 未來的 A 賽或 B 賽有任何一場是越野賽或百岳 → 越野；(b) 否則下一場 A 賽是路跑賽 → 路跑；(c) 否則照近 12 週越野＋登山佔比（≥ 25 % 越野）；(d) 沒資料 → 越野。② C 賽不算。③ 理由文字寫出是哪一場，例如「B 賽『XX 越野』是越野賽」。④ 測試：A 路跑＋B 越野 → 越野；A 路跑＋B 路跑 → 路跑；只有 B 百岳 → 越野；只有 C 越野 → 照佔比。⑤ 只影響設定為「自動」的人；手動選了的不變 |

假設：B 賽沒有時間窗，和現在的 A 賽規則一樣，只要是未來的賽事就算。如果太遠的 B 賽（例如半年後）不該影響現在的圖表和課表，要再加一個窗口。

## 8. 限制

- 沒有讀任何活動資料，所以「越野下坡步頻常低於 130」是使用者的觀察，裝置在低步頻時有沒有衝擊值也沒有確認。
- 步頻降低膝蓋負荷的證據 [D21] 是肌骨模型和跑步，下坡走路沒有直接研究（推估）。
