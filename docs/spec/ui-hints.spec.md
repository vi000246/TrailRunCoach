# Module Spec: ui-hints (提示分類、提示多寡與每頁上限)

> **Last Updated**: 2026-10-13
> **Status**: Active（共用底層 SP-482；各頁掛上是 SP-483～488）
> **Domain Layer**: Supporting
> **Source**: [docs/research/ui-hint-audit.md](../research/ui-hint-audit.md)（SP-305 調查）§1 盤點、§4 提示多寡、§5 聰明顯示、§7 T1

## Overview

頁面上的每一則提示（週備註、計算機警告……）都帶同一個物件，前端用同一套規則決定顯示在哪裡：

```
{id, cls, prio, smart, text, detail, show, ack, fp}
```

| 欄位 | 意思 |
|---|---|
| `id` | 盤點表的編號（GL1、OV8b、RC14…，見下方「每個 id」），`backend/engine/hints.py:CATALOG` |
| `cls` | 1 會改變行動或安全（三段都顯示、不受上限）· 2 有用但不急 · 3 很少用到或重複 |
| `prio` | §5.2 的排序：1 安全與傷病 · 2 課表已改或要確認 · 3 比賽來不來得及 · 4 資料錯到會讓建議錯 · 5 本週要做的事 · 6 其他解釋 |
| `smart` | §5 的聰明條件（R1–R16）成立；◐ 只在成立時直接顯示。條件由各頁的單計算（SP-483～488），還沒算的是 `true` |
| `show` | 三個符號，依序是完整／標準／精簡：● 直接顯示 · ◐ 條件成立才顯示 · ▷ 收進「詳細」 · ✕ 不顯示 |
| `ack` | 可以按「知道了」。第 2、3 類都可以；第 1 類只有目錄標 `ack` 的（OV8b B 賽警告，R7） |
| `fp` | 條件指紋：「知道了」只對同一個指紋有效，條件變了（日期、距離、比賽）就重新出現。沒給就用 id＋文字算 |
| `detail` | 第二層說明（可空） |

## 提示多寡（`ui.hint_level`）

設定 → 個人資料，「跑步經驗」下面三選一（`backend/static/settings.html:218`，`renderHintLevel` `:918`）：

| 值 | 畫面 | 給誰 |
|---|---|---|
| `full` | 完整 | 剛開始跑、第一次用 |
| `standard` | 標準 | 多數人 |
| `lean` | 精簡 | 老手 |
| `null` | 自動 | 沒選過 |

**自動**（`hints.auto_level`，`backend/engine/hints.py:439`）：
- **完整**：資料不夠（`experience.has_history` 為否：沒有連續 4 個完整週、每週 ≥ 3 天跑步或健行）**而且**問卷說是新手（沒答、不能連續跑 30 分鐘、每週 < 3 次，或最長 < 60 分）。
- **標準**：其他所有人，包括擁有者；資料讀不到（`has_history` 為 `None`）也是標準。
- **精簡不會自動選到**（使用者 2026-10-13）。有歷史資料、近一年有比賽成績（`race_results`）、近 12 週最長一次 ≥ 120 分的人，在設定頁問一次「要改成精簡嗎？」（`hints.suggest_lean` `:448`）；按「不要」記成 `ui.hint_ack` 的 `ask.lean`，不再問。

畫面寫「目前：自動（標準）」或「目前：精簡（你選的）」；選過之後有「改回自動」。

## 五步過濾（§4.4，`backend/static/hints.js:45` `Hints.filter`）

1. **類別**：第 1 類直接到第 5 步（三段都顯示、不看符號、不受上限）；目錄標 `ack` 的第 1 類按過「知道了」就收進「詳細」。
2. **等級**：查 `show` 在使用者等級的符號：✕ 不顯示；▷ 收進「詳細」；◐ 到第 3 步；● 到第 4 步。
3. **聰明條件**：`smart` 為 `false` → 收進「詳細」。
4. **知道了**：`(id, fp)` 在 `ui.hint_ack` 裡 → 收進「詳細」（有「再提醒我」）。
5. **上限與排序**：第 1 類全部合併成一個框（`.hint-must`）；第 2、3 類照 `prio`、日期新的先、原順序排，取前 **3** 則（`hints.CAP`），其餘收成「還有 N 則提醒 ▸」，後面接「提示太多？」連到 `設定#hint-level`（示範版沒有設定頁，不顯示連結）。

舊格式（純字串）當第 2 類、`●●●`、不能按知道了：照舊顯示。

`Hints.render(list, {level, acks, cap, item})` 回 `{html, detailHtml, counts}`；`item(h)` 是頁面自己的單則樣子，`detailHtml` 放進頁面的「詳細」。`Hints.state()` 每頁只打一次 `GET /profile/hint-level`，離線或失敗就當標準、沒有知道了。`Hints.bind(root, redraw)` 處理「知道了」「再提醒我」。

## API（`backend/api/plan.py`）

| 方法 | 路徑 | 說明 |
|---|---|---|
| GET | `/api/v1/plan/profile/hint-level` | `{level, chosen, auto, auto_level, reason, has_history, suggest_lean, acks, levels, cap}`（`:607`） |
| PUT | `/api/v1/plan/profile/hint-level` | `{level: full\|standard\|lean\|null}`；回同上（`:618`） |
| POST | `/api/v1/plan/profile/hint-ack` | `{id, fp, undo?}`：「知道了」或「再提醒我」；id 要在目錄裡（或 `ask.lean`）（`:639`） |

## 設定鍵（`backend/settings/repository.py` DEFAULTS）

| key | 預設 | 驗證 |
|---|---|---|
| `ui.hint_level` | `None` | `hints.validate_level`：full／standard／lean／null |
| `ui.hint_ack` | `[]` | `hints.validate_acks`：`[{id, fp, at}]`，最多 300 筆、同一 (id, fp) 不重複；超過丟最舊的（`hints.with_ack`） |

兩個都是 `user_settings` 的使用者選擇（`data_registry` USER，會進備份、不是 LOCAL）。

## 後端怎麼帶

- **週備註**（總覽 `GET /overview/weekplan`、課表 `plan_notes`）：在 API 層把 `{level, src, text}` 加上提示欄位（`hints.note` `:377`；`backend/api/overview.py` weekplan、`backend/api/plan_sessions.py:_plan_notes`）。`src` 對到 OV8a–k（`hints.NOTE_SRC` `:348`）；沒有 src 的 watch／bad 是 OV8k（照抄指標）、info 是 OV8g；不認得的 src 用 OV8，`bad` → 第 1 類。`level` 保留給顏色。B 賽警告（`post_race.b_hints`）帶條件指紋 `fp`（B 賽／A 賽的名稱、日期、距離）。
- **計算機警告**：引擎裡仍是字串，但每句用 `hints.tag(id, text)`（`Tagged`，`str` 的子類，舊的字串比對都照常）標上 id；回應時 `calc.respond`（`backend/engine/racepower/calc.py:792`）把 `warnings`、`course_warnings`、`fuel.warnings` 轉成物件（`/plan`、`/predict`、`/course`、`/course/event/{id}`，靜態示範的 worker 走同一個函式）。沒標的字串（舊存檔、分享）變 id `RC`、照舊顯示；前端 `racepower.html`、`share.html` 兩種格式都吃。
- 第 1 類的特例（例如可信度低、沒有體重）由產生的地方帶 `cls=1`（`Tagged.hint_cls` 或 `make(cls=)`），`show` 會變成 `●●●`。

## 每個 id

類、三段的顯示方式、排序。來源是 `backend/engine/hints.py` 的 `_ROWS`，`backend/tests/test_hints.py` 檢查這張表和程式一致、盤點表的每個 id 都在。「類」欄的「（cls N：見備註）」是同一列在某個情況的另一類。

**第 1 類一律顯示**：表上第 1 類的符號沿用盤點表（例如 OV8c 碳水負荷週 `●●▷`、RC2 降雨 `◐◐◐`），但過濾時第 1 類不看符號（驗收：第 1 類三段都顯示）；RC2 的 ◐ 是 R1 決定放頂端框還是天氣卡一行，由 SP-485 處理。

**盤點表之外加的 id**：`RC`（計算機沒標 id 的句子）、`RC3w`（冷風，SP-251）、`RC3h`（失溫，SP-253）、`RC13a`（百岳高山症）。SP-251、SP-253 在盤點之後已實作（`calc.cold_reminders`），直接登記成第 1 類。

## Known limits

- 預設條件指紋是 id＋文字：沒帶 `fp` 的提示，切換語言後文字不同，「知道了」要重按一次；週週數字會變的句子（例如 CTL 掉了 N%）數字一變就重新出現。B 賽警告已帶自己的 `fp`，不受影響。
- 聰明條件（R1–R16）還沒算，`smart` 都是 `true`；◐ 在標準／精簡都等於 ●，直到各頁的單補上。
- 週備註的 OV8g 裡「剩下每天都排了」那句（第 3 類）和 OV8k，現在靠「沒有 src」辨認；`overview.py` 給它們 src 之後改成直接對應（SP-483）。
